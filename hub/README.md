# 縁泉ハブ(いまの縁泉スプレッドシートとの同期)

ホーム画面の縁泉アプリと、いまの縁泉スプレッドシート `ensen` をつなぐ受け口です。費用はかかりません。

- 縁は今まで通り `ensen` の `events` シートに入ります。縁泉のGASアプリ・iOSの自宅オートメーション・写真の痕跡ショートカット・夜間エンリッチもそのまま動き、どこで入った縁もアプリに届きます。
- アプリのデータは端末の中にもあり、圏外でも書けます。開いたとき・戻ったとき・書いてから数秒後に、変わった分だけをやり取りします。
- 縁泉の規約を守ります。`events` と `appraisals` は**追記だけ**(既存の行は直さない・消さない)、語彙(5種・動詞7語)は検査だけ、`intents` の状態はアプリで本人が「試した」「手放す」を押したときだけ変えます。

## スプレッドシートに足されるもの

| 場所 | 中身 |
|---|---|
| シート「_sync」 | kind, id, rev(変更の連番), mtime, deleted, hash。同期のための表なので触らないでください |

ほかのシートの列の形は変えません。アプリで結んだ縁は `source` 列が `home` になります。台帳 `actants` の照合(場所=名前が似ていて150m以内、ほか=名前・別名の一致)と `last_seen`・`count` の更新は、縁泉GASと同じ規則で行います。写真を付けた縁は、縁泉と同じ Drive の `ensen_media` フォルダに写真を置き、`media_ref` にURLを入れます。

## 準備(最初の1回、パソコンで行うのが楽です)

1. https://script.google.com で「新しいプロジェクト」を作ります(名前の例: 縁泉ハブ)。スプレッドシートに付ける必要はありません。
2. 最初からある `コード.gs` の中身を全部消して、[Code.gs](https://raw.githubusercontent.com/tadamasa/ensen-home/main/hub/Code.gs) の中身を貼り、保存します。
3. 上の関数の選択欄で `setup` を選び、「実行」を押します。
   - 権限の確認が出たら、自分のアカウントを選び、「詳細」→「(安全ではないページ)に移動」→「許可」と進みます。スプレッドシート(縁泉・日記・読書・映画を読むため)、Drive(写真を置くため)、外部への接続(近くの場所の候補のため)の3つです。
   - 下の実行ログに「合言葉: …」が出ます。これを控えます。
4. 左の「ライブラリ」の **+** を押し、スクリプトID `1AERbCrDNFVHKT1YDCTSensHNs4X8QrACyaS-p3xDFhqrUq2r7NGMuMwk` を貼って「検索」。バージョンは **1**(数字を選ぶ。「HEAD(開発モード)」は選ばない)、ID は **DayReaders** のまま「追加」。泉の「この日の日記・本・映画」と月の印を読む共通ライブラリです(下の「その日のまわり」)。
5. 右上の「デプロイ」→「新しいデプロイ」を開き、種類の歯車から「ウェブアプリ」を選びます。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
   - 「デプロイ」を押し、出てきた「ウェブアプリのURL」(`…/exec` で終わるもの)をコピーします。
6. 縁泉アプリの「設定」→「縁泉ハブ(同期)」に、URLと合言葉を入れて「接続して同期する」を押します。最初の1回はこれまでの縁(約2800件)・台帳・写真の痕跡を全部受け取るので、1〜2分かかります。

URLと合言葉を知っている人は縁泉を読み書きできるので、他の人には教えないでください(縁泉GASの取込口とは別の合言葉です)。

## スクリプトを新しくするとき

Code.gs を貼り替えて保存したら、「デプロイ」→「デプロイを管理」→ 鉛筆の印 → バージョン「新バージョン」→「デプロイ」。URLは変わりません。

### 2026-11-02 の更新(DayReaders への乗り換え)で一度だけすること

1. 左の「ライブラリ」の **+** で DayReaders(上の準備の4)を版 **1** で追加します。
2. `Code.gs` と `SpotMatch.gs` を貼り替えて保存し、「新バージョン」で出し直します。
3. 初めての同期で、試す(intents)とスポットの修正(spot_fixes)を全件アプリへ送り直します(返す形に印を足したため。数十秒かかることがあります)。

ライブラリを追加する前に新しい Code.gs を貼っても、同期は今まで通り動きます。泉の「この日の日記・本・映画」と月の印だけが「ライブラリ DayReaders が追加されていません」という理由つきで空になります。

## その日のまわり(DayReaders)

日記・読書ハブ・映画ハブを読むコードは、共通ライブラリ **DayReaders**(tadamasa/diary-home の [lib/day-readers](https://github.com/tadamasa/diary-home/tree/main/lib/day-readers))にまとめました。日記ハブ・日記v2 も同じものを使います。
このハブはスクリプト プロパティ(下の表)からシートIDとアプリURLを決め、引数で渡すだけです。ライブラリは版を固定して追加します(開発モードは使わない)。いまの版は `appsscript.json` の `dependencies` と、上の README の「他アプリとの約束」に書いてあります。
ライブラリの版を上げるときは、エディタ左の「ライブラリ」→ DayReaders → 版を選び直して保存 →「新バージョン」で出し直し、`appsscript.json` と `tests/lib/DayReaders.gs`(テスト用の写し)も同じ版にそろえます。

## spot_fixes を読む相手(旅先)との約束

`spot_fixes`(fix_id, ts, actant_id, event_id, lat, lng, status, source)は追記専用で、縁泉アプリと旅先(tadamasa/tabisaki)が読みます。

- **ts の書式**: `yyyy-MM-dd'T'HH:mm:ss+09:00`(東京時間・秒まで・ミリ秒なし・オフセットは必ず `+09:00`)。例 `2026-11-02T14:05:09+09:00`。
  - ハブは書き込みの入口(`spotTs_`)で、受け取った値をいったん日時にしてから、この形に書き直します。`Z`・ミリ秒付き・ほかのオフセットは東京時間に直し、オフセットのない値は東京時間とみなします。読めない値・空は受け取った時刻にします。
  - `SpotMatch.gs`(source=auto)も同じ関数を通します。手で表に行を足すときもこの形で書いてください。
  - 読む側は、日時に直さず**文字列のまま大小を比べてよい**(この書式なら文字列の順と時刻の順が同じ)。
- **効く行**: 同じ `actant_id` の行のうち、`ts` がいちばん新しい1行だけが効きます(`move`=lat/lng へ置き直す、`hide`=位置不明、`ok`=確かめた、`undo`=元に戻す)。
- **同じ秒のとき**: `ts` が同じなら、**後に追記された行(シートで下の行)が勝ちます**。比べるときは `>=` で、上から順に読みながら置き換えます。アプリにはハブが行番号(`seq`)を付けて渡し、`js/ensen.js` の `latestSpotFixes` も同じ規則にしています。
- 2026-11-02 に events の lat/lng を修正後の座標に書き換えました(控え events_backup_20261102)。spot_fixes を重ねて当てても同じ座標になるだけです。今後の位置修正も spot_fixes に追記します。

## 設定で変えられるもの(スクリプト プロパティ)

| キー | 既定 |
|---|---|
| `ENSEN_SHEET_ID` | 縁泉 `ensen`(1vKPwd3k…) |
| `ENSEN_MEDIA_FOLDER_ID` | (なし)= Drive の `ensen_media` フォルダを名前で探す |
| `GOOGLE_PLACES_API_KEY` | (なし)= 近くの場所の候補は、台帳の150〜300m以内だけ。縁泉GASと同じキーを入れると Google の候補も出ます |
| `DIARY_SHEET_ID` / `DIARY_APP_URL` | 「日記の記録」と日記アプリ |
| `BOOKS_SHEET_ID` / `READING_APP_URL` | 読書ハブと読書メモアプリ |
| `MOVIES_SHEET_ID` / `MOVIE_APP_URL` | 映画ハブと映画メモアプリ |

日記・読書ハブ・映画ハブは、泉の画面の「この日の日記」「この日に読み終えた本・観た映画」のために読むだけで、書き込みません。

## スポットの位置を店の名前で直す(SpotMatch.gs)

Swarm から取り込んだ場所の緯度経度は「チェックインした時の iPhone の位置」なので、家などから後でチェックインした店がそこに重なっています。店の名前で地図を引き直して、正しそうな位置に自動で直します。

1. スクリプトエディタの「ファイル +」→「スクリプト」で `SpotMatch` を作り、[SpotMatch.gs](https://raw.githubusercontent.com/tadamasa/ensen-home/main/hub/SpotMatch.gs) の中身を貼って保存します。`Code.gs` も最新に貼り替えます。
2. 「プロジェクトの設定」→「appsscript.json をエディタで表示する」をオンにして、[appsscript.json](https://raw.githubusercontent.com/tadamasa/ensen-home/main/hub/appsscript.json) の中身に貼り替えます(続きを自動で走らせる権限が増えます)。
3. 関数 `matchSpots` を選んで「実行」。権限の確認が出たら許可します。約1,750か所を照会し、5分ごとに区切って1分後に自動で続きを走らせます(全部で30〜60分)。結果はシート `spot_match` に入り、縁は書き換えません。
4. 終わると実行ログ(または「実行数」)に「そのままで正しい ○・置き直す ○・わからない ○」と出ます。`spot_match` を眺めて、よければ `applySpotMatches` を実行します。`spot_fixes` に `source=auto` の行が足され、アプリは次の同期で位置を直します。
5. 戻したいときは `undoAutoSpotFixes`。自動で足した修正だけを打ち消します(手で直したものはそのまま)。

照会先は OpenStreetMap(Nominatim、1秒に1回)と Google の Maps サービス(Apps Script に組み込み)です。スクリプト プロパティに `GOOGLE_PLACES_API_KEY` があれば Google Places でも引きます(店名にいちばん強い)。チェーン店のように同じ名前が何か所もあるもの、照会先が食い違うものは「わからない」にして、アプリの「確かめる」で手で直します。
